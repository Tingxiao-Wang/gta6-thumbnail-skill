## V1.6 强制加入提示词的版式编译合同（优先于旧版宽泛风格说明）

从 `references/platform_layout_rules.json` 读取当前平台的 `output`、`headline_size`、`layouts`、`title_design`、`screenshot_processing`。必须先选定唯一 `layout_id`；如果用户要求B站4:3或YouTube Shorts 9:16，要使用 `ratio_layout_overrides` 独立重构。将其 `headline_rect/tag_rect/subtitle_rect/hero_rect` 及主标题整体块高目标写入内部 `design_brief`，再组装下面的最终提示词。

- 画幅：平台默认尺寸或用户指定尺寸。B站V1.6创作主版为16:9；有4:3要求时另作一版。
- 素材保真：指定哪些人物、车、地标、构图关系不可变。
- 主视觉与文字：明确主视觉所在区域、标题框及语义断行；标题原文必须一字不改。
- 二次包装：基于截图局部调色、标题后方托底、主体清晰化和背景层次，必须做出视觉改进但不过度滤镜。
- 强禁止：无外框/灰底/纸质海报样机/无关新主体/平台播放量与时长/虚假游戏事实。
- 检验与诚实降级：纯生成模型无法确保精确坐标时不能假装已严格按像素排版；可独立叠字时优先叠字。

**长标题处理**：不要为了匹配推荐字数擅自改写，允许按语义拆出“引入词/核心钩子”两层，但合并后字符串必须与用户原文严格一致（除排版换行）。禁止添加用户未输入的标点。


# GTA Thumbnail Pro V1.5 — 生成与修正协议

## 先做创作决策（V1.4 新增）
生成前先执行 `clarification_rules.json`，只在真正缺失内容方向且会显著影响结果时给出建议/追问；用户已明确或要求立即生成时不得阻拦。
若用户选择了一个方案，按 `design_brief_schema.json` 合并已有上下文和选择，才能继续下列提示词编译步骤。优先复用 `decision_catalog.json` 已有的具体类型与9种风格，不得在最终生图提示词中泄露内部JSON。

## 提示词编译顺序
按以下顺序组合（不要把整个 JSON 原样塞给绘图工具）：
1. **真实任务**：平台、视频主题、目标用户、成品用途、允许使用的上传图。
2. **画幅**：明确比例与可提供的目标像素（需要核验后才宣称实现）。
3. **核心事实**：真实主体/事件与“不得编造”的边界。缺少原图时用原创概念场景。
4. **风格配方**：`styles.json` 选出的主配方 `prompt_core`、可操作参数、强制禁用项。
5. **构图**：按 `composition.json` 的 ratio profile 指定主视觉和标题区域；坐标是设计意图不是像素硬约束。
6. **标题**：严格引用用户指定标题，包括中英文字、数字、标点、大小写；没有则按 `typography.json` 创建。
7. **质量**：高质量但不过度饱和、无多余图标/水印/UI、手机缩略可辨识。
8. **输出**：直接调用当前可用的图片工具；不可用则只返回提示词，不伪装已出图。

## 组装示例（不是固定画风）
为【B站】制作【4:3】的 GTA 风格原创游戏封面。视频内容：【夜间警车追逐】；若有用户上传游戏截图，则以原图为准，保留同一车辆和道路细节；没有就生成明确的概念场景。风格【gameplay_question】。主体在视觉中心偏右，左侧保留单块标题空间；色调低饱和夜景、红蓝反差仅用于警灯，不使用随机光束。准确写入标题「【用户原文】」，不修改任何字。不要游戏Logo、平台UI、时长水印、未提供的主播肖像。按目标比例成图，检查文字和主体完整性。

## 工具选择
- 同时有图像编辑、可控文字叠加：先无字场景，再叠准确标题；修改时优先编辑已有图。
- 只有一次性文生图：使用清晰标题与视觉指令；若中文错字，无法精准修正则出无字底图并告知手动叠字方案。
- 仅有文字能力：返回一条完整生图提示词 + 可选标题布局建议，明确“当前未生成图片”。

## 多比例构图策略
- 小红书3:4：主体中下，标题上方，不能把横版的左右并排主体强行压缩成竖版。
- B站4:3：主要内容集中可见，不能把16:9拉伸成4:3。需要16:9时额外重排。
- YouTube16:9：一个鲜明焦点+清楚短标题，不强制英文。
- Shorts9:16：关键故事和标题尽量在竖屏中心安全位置，避免上/下 UI 可能覆盖区。
- 对比型竖版：优先上下对照；横版：优先左右对照；保持来源、尺度、标签清晰。

## 局部编辑提示词模板
编辑已有图片【实际可访问的图片引用】。只修改【changed_fields】。严格保留【locked_fields】中的标题原文、真人身份、主要车辆外形、事实证据、场景故事，不新增Logo/平台UI。修改后核验保留项；若宿主只能重生成，说明无法保证像素级完全一致。

## 检查与失败标签
- `OUTPUT_NOT_GENERATED`：没有生图工具。
- `TEXT_NEEDS_OVERLAY`：标题字形/字符不可靠，已生成无字图并提供标题说明。
- `RESOLUTION_UNVERIFIED`：无法核实最终像素。
- `IDENTITY_NOT_GUARANTEED`：没有足够编辑能力维持完全相同面部/车辆细节。
- `SOURCE_EVIDENCE_MISSING`：用户要求真实BUG/数据/对比但缺乏证据。不得将推测转为事实。
这些标签可用于内部质检；普通用户输出时用简明中文/英文说明，无需罗列内部代码。

## V1.5 截图型封面（小红书/B站/YouTube共用）
优先级：真实可访问用户截图 → 锁定其可见主体、场景和核心事件 → 选择平台画幅 → 读取 `screenshot_cover_rules.json` 共通指令 → 读取 `platforms.json` 平台差异 → 核验宿主图像编辑/文字叠加能力 → 实际执行。

**图像编辑生成指令模板（只在有可访问真实源图时使用）**：
“以当前上传的【用户截图】作为**唯一核心素材**，制作【平台】【比例】的专业游戏视频封面。保留截图中实际可见的【人物/车辆/地标/镜头关系】与故事事实，画面铺满整个成品边缘（full bleed）。为【内容类型】创造【电影化或信息型】视觉表达：局部光影、画面纵深、统一色调、清晰主体分离，优先利用截图原有负空间安排文字。用户主标题严格为「【原文标题】」，可以换行不能改字。可选非事实性辅助标签，仅当提供或必要时使用。**禁止**灰色或白色外底、截图嵌在相框里、纸质海报/屏幕样机、厚边框、无关新增跑车人物、平台UI、虚假 GTA 官方标志。不简单贴字；画幅变更需重构而非拉伸。按可用工具完成并核验实际出图。”

**平台插入差异**：
- 小红书：3:4，竖版画面延展与主体居中，强可读标题但不强迫黄字；不可把横版截图缩入白底。
- B站：4:3优先，双比例另做16:9；真实场景故事和层次更重要；不是“电影海报实体相框”。
- YouTube：16:9，少量高对比文字+单一主焦点，保持用户标题语言；Shorts需另做9:16。

**失效回退**：原图不可访问→不要声称已编辑；编辑器只支持生成→说明相似度可能不稳定；精确文字不可控→给无字底图与准确文字叠加说明；导出无法核实→只报工具已核实的比例/尺寸。
