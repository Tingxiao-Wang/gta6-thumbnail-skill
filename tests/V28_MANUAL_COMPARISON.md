# V2.8 失败案例复测｜同题 A/B/C 对照

使用你已经给出的 WorkBuddy 原生 vs V2.7.2 Skill 封面对比作为**基准案例**，本包不内嵌第三方游戏截图或用户的图片；测试时由用户在宿主中实际提供。

## 共同任务

- 平台：B站 16:9。
- 主题：GTA6 剧情万字解析。
- 标题：`万字解析：GTA6到底讲了什么故事？`
- 可选标签：只有用户提供“全网首发”时才允许显示；默认不添加。
- 输入：与原生模式相同的用户可用图片或素材。若照片是本人真人，沿用原像素保护；不可默许重绘。

## 一次 A/B/C 的预期视觉组织

| 方案 | 视觉故事 | 非文字设计 | 标题关系 |
|---|---|---|---|
| A：S01 电影叙事 | 角色间的情绪与城市环境共同表达“故事” | 前后景、人物距离、远景与近景的对照 | 「万字解析」上层辅助，「GTA6」独立主词，「故事问题」作为悬念 |
| B：S05 编辑叙事 | 主画面与有内容价值的辅图/概念图共同表达“深度解析” | 大主图、非对称信息区域、有效留白 | 不得挤成下沿统一字幕 |
| C：S06 背景巨字 | 字形与人物交错形成视觉空间 | 大字图形体块+前景主体；真遮挡需要蒙版 | 文字成为场景结构，不是纯字幕 |

## 如何判定改善

1. 遮掉文字：是否还看得出三种不同的画面组织？
2. 缩小到移动端：第一眼是否能分清主词/故事悬念/人像主体？
3. 同条件下是否至少在视觉叙事、非文字设计、文字层级三项里有明确优势？
4. 有无虚构游戏剧情、编造官方消息、替换用户真人照片等硬性问题？

将两张真实成品的人工或视觉模型得分填入同目录 `v28_manual_score_template.json`，运行：

```sh
python scripts/visual_benchmark_v28.py --review tests/v28_manual_score_template.json
```

模板默认 `actual_images_reviewed=false`，因此会输出 `needs_real_images`，不能直接得到“通过”。
